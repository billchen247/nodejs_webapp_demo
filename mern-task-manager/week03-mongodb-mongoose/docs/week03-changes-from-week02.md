# Week 3 — Changes from Week 2

## What We Had Before

- Express app with full CRUD.
- Data stored in a **JavaScript array in memory** (`src/data/tasks.js`).
- Integer ids generated by a `nextId()` helper.
- No persistence — data vanished on every restart.

## What We Added

- MongoDB persistence via **Mongoose**.
- `src/config/database.js` to centralize the connection logic.
- `src/models/Task.js` — a schema with validation (`required`, `maxlength`, `trim`) and automatic `createdAt` / `updatedAt`.
- Environment-based configuration using `dotenv` and `MONGODB_URI`.
- Clear 400 vs. 404 vs. 500 behavior.

## What We Changed

- `src/controllers/taskController.js` — all handlers are now `async` and use Mongoose methods.
- `src/server.js` — connects to MongoDB **before** `app.listen`.
- `.env.example` — added `MONGODB_URI`.
- `package.json` — new dependencies, updated name/description.

## Architecture Change

```
Week 2                               Week 3
-------                              -------
in-memory array (RAM)             →  MongoDB collection "tasks"
Array.find / splice / push        →  Task.find / findByIdAndUpdate / ...
integer id via nextId()           →  ObjectId assigned by MongoDB
no validation                     →  schema validation (400 on fail)
sync handlers                     →  async/await handlers
```

## New Concepts

- **MongoDB**: database → collection → document.
- **Mongoose schema** and **model**.
- **ObjectId** vs. integer id.
- **Validation errors** vs. **not-found** vs. **invalid id**.
- **Async controllers** using `async`/`await`.
- **Environment-based** configuration via `dotenv`.

## Why We Made These Changes

In-memory data is unusable for anything beyond a demo. Real applications
need persistence. MongoDB is the "M" in **MERN**, and Mongoose is the
industry-standard way to use it from Node.js. Introducing it here —
before React — lets students focus on **one new idea at a time**.

## Classroom Demonstration

1. Stop any running Week 2 server. Open MongoDB Compass.
2. `npm run dev`. Confirm "Connected to MongoDB: taskmanager".
3. `curl -X POST ...` to create a task. Watch it appear in Compass.
4. Restart the server. The task is still there — **persistence**.
5. `curl -i http://localhost:5000/api/tasks/zzz` → **400** (invalid id).
6. `curl -i -X POST .../api/tasks -H "Content-Type: application/json" -d '{}'` → **400** (validation).
7. Delete a task; re-GET it → **404**.
